# Архитектура и развитие

## Текущая версия

Клиентское приложение без сборки: HTML + CSS + ES modules. Node-сервер раздаёт только публичные HTML/CSS/JS/SVG файлы. Состояние — один JSON в localStorage (`soputnik-v1`). Демооперации не создают сетевых запросов к партнёрам. Сведения из приложенных диаграмм использованы как требования к пользовательским сценариям; приложенный HTML содержал только стартовую оболочку.

Сущности: профиль и пять сфер жизни; цели; отклики; встречи; обращения со статусами «Новое → В работе → Завершено»; согласование куратора; текст резюме. Взрослый участник может откликаться самостоятельно, несовершеннолетний — после заполнения анкеты и согласования. Курсы и помощь открыты независимо от согласования.

## Целевая серверная схема

Браузер → API с серверной сессией → PostgreSQL. Отдельные адаптеры к СберID, Работа.ру и ИИ. Задания уведомлений через очередь; интерфейс координатора должен получать подтверждения доставки. Ключи провайдеров находятся только на сервере. Правила доступа проверяются на каждой операции и по связи участника с конкретным куратором/ментором. Демо-переключатель роли заменяется назначенными ролями.

Основные таблицы: users, profiles, sphere_assessments, role_assignments, participant_assignments, consents, curator_approvals, goals, opportunities, applications, resumes, meetings, support_requests, support_events, audit_events. Согласование должно быть версионируемым, с автором, временем, основанием и отзывом.

Этапы до реальной эксплуатации:

1. Согласовать полномочия взрослых, обработку данных, сроки хранения, согласия, регламент кризисной помощи и ответственных координаторов.
2. Реализовать сессии, серверный RBAC, БД, миграции, аудит и резервное копирование; покрыть права доступа негативными тестами.
3. Подключить СберID через зарегистрированное приложение; проверить возрастную маршрутизацию и отзыв согласований.
4. Согласовать интеграцию Работа.ру и её API/формат экспорта; добавить вакансии, отправку резюме только с отдельным подтверждением пользователя и статусы доставки.
5. Подключить ИИ через серверный адаптер: минимизация данных, ограничения рекомендаций, подтверждённый канал передачи человеку. Ответ модели не является подтверждением оказанной помощи.
6. Реализовать календарь, уведомления, правила эскалации и рабочие смены координаторов; провести сквозные проверки с реальными партнёрами.
7. Добавить мониторинг, ограничения запросов, доступность, проверку безопасности и восстановление из резервной копии перед запуском.

Завершение трека и портфолио выпускника, полноценная публикация вакансий, подбор ментора и межпользовательский обмен остаются следующими этапами, не имитируются как подключённые функции.
